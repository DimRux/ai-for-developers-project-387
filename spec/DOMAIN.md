# Доменная модель и API-контракт календаря бронирований

Лёгкий аналог cal.com. Единственный источник правды — ТЗ: две роли (владелец календаря и гость),
без регистрации и авторизации, окно записи 14 дней, глобальная занятость календаря.

Контракт: [`main.tsp`](./main.tsp) → генерируется в [`generated/openapi.yaml`](./generated/openapi.yaml).

## Доменные сущности

### Owner — владелец календаря

Единственный заранее заданный профиль. Не создаётся и не регистрируется через API: только читается.
По умолчанию используется в административной части и владеет всеми типами событий и бронированиями.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string` | Идентификатор владельца |
| `name` | `string` | Отображаемое имя |
| `email` | `string` (email) | Контактный email |
| `timezone` | `Timezone` (IANA) | Часовой пояс, в котором трактуются рабочие часы |
| `workingHours` | `{ start, end: plainTime }` | Рабочие часы внутри дня, например 10:00–19:00 |
| `slotStepMinutes` | `int32` = `30` | Шаг сетки слотов: допустимые значения начала встречи |
| `bookingWindowDays` | `int32` = `14` | Глубина окна записи в днях от текущей даты |

### EventType — тип события

Создаёт владелец. По ТЗ владелец задаёт `id`, название, описание и длительность в минутах.
Длительность определяет длину слота и время окончания брони.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string` (1–64) | Задаётся владельцем, уникален, используется в публичных ссылках |
| `title` | `string` (1–200) | Название, которое видит гость |
| `description` | `string` (≤2000) | Описание встречи для гостя |
| `durationMinutes` | `int32` (1–1440) | Длительность встречи |
| `createdAt` | `utcDateTime` | Момент создания (read-only) |

Форма создания — `EventTypeCreate` (`id`, `title`, `description`, `durationMinutes`).

### Slot — слот

Вычисляемая сущность, **не хранится**. Слоты строятся на лету:

1. берётся окно `[windowStart; windowEnd)`, по умолчанию `[сейчас; сейчас + bookingWindowDays)`;
2. внутри каждого дня окна берутся моменты, кратные `Owner.slotStepMinutes`, в часовом поясе владельца;
3. слот имеет длину `EventType.durationMinutes` и должен целиком укладываться в `Owner.workingHours`;
4. слот помечается занятым, если пересекается с любым существующим бронированием календаря.

| Поле | Тип | Описание |
| --- | --- | --- |
| `start` | `utcDateTime` | Начало слота |
| `end` | `utcDateTime` | `start + durationMinutes` |
| `isAvailable` | `boolean` | Свободен ли слот |

Слоты отдаются сгруппированными по дням (`DaySlots { date, slots }`) внутри `SlotsResponse`,
включая дни без свободного времени — это нужно для отрисовки календаря на 14 дней.

### Booking — бронирование

Создаёт гость на выбранный слот. Аккаунт не создаётся: гость передаёт только время начала и контакты.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `string` | Идентификатор бронирования |
| `eventTypeId` | `string` | Тип события, на который создана бронь |
| `eventTypeTitle` | `string` | Название типа события на момент бронирования (снимок) |
| `start` | `utcDateTime` | Начало встречи (пришло от гостя) |
| `end` | `utcDateTime` | `start + EventType.durationMinutes`, вычисляет сервер |
| `guest` | `Guest { name, email, notes? }` | Данные гостя |
| `createdAt` | `utcDateTime` | Момент создания брони |

Форма создания — `BookingCreate { start, guest }`.

## Инварианты домена

1. **Глобальная занятость календаря.** Бронь нельзя создать, если полуинтервал `[start; end)`
   пересекается с `[start; end)` любого существующего бронирования — **даже если это другой тип
   события**. Нарушение → `409 SLOT_TAKEN`. Тот же критерий используется при генерации слотов
   (`Slot.isAvailable = false`).
2. **Окно записи.** Допустимы только `start` внутри `[сейчас; сейчас + bookingWindowDays)`
   (по умолчанию 14 дней). Прошлое время и время за границей окна → `400 SLOT_OUT_OF_WINDOW`.
3. **Сетка и рабочие часы.** `start` кратен `Owner.slotStepMinutes` и `start + durationMinutes`
   не выходит за `Owner.workingHours` того же дня. Нарушение → `400 SLOT_NOT_ALIGNED`.
4. **Длительность считает сервер.** Гость не может задать `end`: он выводится из
   `EventType.durationMinutes`.
5. **Уникальность типа события.** `EventType.id` задаёт владелец; повторный `id` → `409 EVENT_TYPE_ID_CONFLICT`.
6. **Нет аутентификации.** Ни одна операция не требует токена; в контракте отсутствует
   `securitySchemes`. Владелец не передаётся параметром — он единственный.

## Публичный сценарий гостя

1. `GET /event-types` — страница видов брони: название, описание, длительность.
2. `GET /event-types/{eventTypeId}` — карточка выбранного типа события.
3. `GET /event-types/{eventTypeId}/slots` — календарь свободных слотов на 14 дней от текущей даты,
   сгруппированный по дням. Без параметров окно берётся по умолчанию: `[сейчас; сейчас + 14 дней)`.
4. `POST /event-types/{eventTypeId}/bookings` с `{ start, guest }` → `201 Booking`.
   Конкурентная запись на то же время → `409 SLOT_TAKEN`.
5. `GET /bookings/{bookingId}` — страница подтверждения созданной встречи.

## Сценарий владельца

1. `GET /admin/owner` — предзаданный профиль, используемый в админке по умолчанию
   (часовой пояс, рабочие часы, шаг сетки, окно записи).
2. `POST /admin/event-types` — создание типа события с `id`, названием, описанием и длительностью.
3. `GET /admin/event-types` — список созданных типов событий.
4. `GET /admin/bookings?scope=upcoming` — страница предстоящих встреч: единый список бронирований
   **всех** типов событий, отсортированный по времени начала по возрастанию. Доступны фильтры
   `from`, `to`, `eventTypeId` и постраничность.

## Матрица покрытия требований ТЗ

| Требование ТЗ | Где зафиксировано в контракте |
| --- | --- |
| Владелец — один заранее заданный профиль, используется по умолчанию | `Owner`, `GET /admin/owner` (профиль не создаётся через API) |
| Нет регистрации и авторизации | Нет `@useAuth` / `securitySchemes`; ни одна операция не требует учётных данных |
| Владелец создаёт типы событий: `id`, название, описание, длительность в минутах | `EventTypeCreate`, `POST /admin/event-types` |
| Владелец видит предстоящие встречи всех типов событий в одном списке | `GET /admin/bookings` (`scope=upcoming` по умолчанию, сортировка по `start`, без обязательного фильтра по типу) |
| Гость видит виды брони: название, описание, длительность | `EventType.title` / `description` / `durationMinutes`, `GET /event-types` |
| Гость выбирает тип события и открывает календарь | `GET /event-types/{eventTypeId}`, `GET /event-types/{eventTypeId}/slots` |
| Свободные слоты на 14 дней от текущей даты | `Owner.bookingWindowDays = 14`, `SlotsResponse.windowStart` / `windowEnd`, `DaySlots`, дефолты `from`/`to` |
| Гость создаёт бронирование на выбранный свободный слот | `BookingCreate`, `POST /event-types/{eventTypeId}/bookings` → `201 Booking` |
| Гость может записаться только на свободный слот из окна | `400 SLOT_OUT_OF_WINDOW`, `400 SLOT_NOT_ALIGNED`, `409 SLOT_TAKEN` |
| На одно время нельзя две записи, даже разных типов событий | `ErrorCode.SLOT_TAKEN` + `Slot.isAvailable`, инвариант 1 |
| Гость не создаёт аккаунт | `Guest` передаётся в теле брони, отдельной сущности пользователя нет |

## Операции контракта

Всего 9 операций:

| Метод | Путь | Ответы | Роль |
| --- | --- | --- | --- |
| `GET` | `/admin/owner` | `200` | Владелец |
| `POST` | `/admin/event-types` | `201`, `400`, `409` | Владелец |
| `GET` | `/admin/event-types` | `200`, `400` | Владелец |
| `GET` | `/admin/bookings` | `200`, `400` | Владелец |
| `GET` | `/event-types` | `200` | Гость |
| `GET` | `/event-types/{eventTypeId}` | `200`, `404` | Гость |
| `GET` | `/event-types/{eventTypeId}/slots` | `200`, `400`, `404` | Гость |
| `POST` | `/event-types/{eventTypeId}/bookings` | `201`, `400`, `404`, `409` | Гость |
| `GET` | `/bookings/{bookingId}` | `200`, `404` | Гость |

Вне объёма ТЗ и потому отсутствуют: изменение и удаление типов событий, отмена и перенос
бронирований, статусы броней, флаги активности типов событий, аутентификация.

## Сборка и проверка

```bash
cd spec
npm install
npm run compile        # tsp compile . -> generated/openapi.yaml (OpenAPI 3.1)
```

Дополнительная проверка сгенерированного документа:

```bash
npx @redocly/cli lint generated/openapi.yaml
```

Линтер сообщает `security-defined` по всем операциям — это ожидаемо и соответствует ТЗ:
авторизация в проекте отсутствует.
